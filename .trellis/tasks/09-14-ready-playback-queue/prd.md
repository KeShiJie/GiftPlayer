# 就绪优先播放队列与弱网下载超时

## 已确认需求

- 新增 `QueuedAnimationPlayerView`，保留旧播放器替换式播放行为。
- `enqueue(request)` 立即准备资源；URL 并发下载，Asset/FilePath 或缓存命中立即就绪。
- 就绪队列按就绪先后串行播放，不抢占当前动画，不等待更早但仍在下载的消息。
- 同资源多条消息独立播放，共享底层下载但不合并播放次数。
- 播放完成/失败自动继续；内部回调不被外部 setCallback 覆盖；回调保留原始请求。
- `clearQueue()` 仅清理等待/就绪任务，`stop()` 停止当前并清队列，`release()` 完整清理。
- 就绪文件保护到播放结束/取消，避免缓存清理删除；共享下载取消不影响其他消费者。
- `AnimationQueueConfig.messageTtlMillis: Long? = null` 默认不过期。配置时从入队计时，开始播放后不再过期。
- 下载连接超时默认 20_000ms、读取超时 30_000ms、总超时 180_000ms，均支持配置且校验正数。
- 总超时从真正启动下载计时，不含等待槽位；失败释放槽位，保留可续传文件。
- 防止超时/取消后旧下载回调干扰同 Key 新任务；取消所有超时定时器。
- SDK 不定义固定的下载或播放优先级枚举，只接收接入方提供的 `Int` 等级；数值越大优先级越高，默认值为 0。
- 下载优先级与播放优先级相互独立。下载优先级只调度等待中的网络任务，播放优先级只排序已经准备完成的播放消息。
- 已准备消息按播放优先级降序、原始入队顺序升序播放。未准备的高优先级消息不阻塞其他已准备消息，也不抢占当前动画。

## 验收

- A 未下载完，缓存 B 可先播；B 播放时 A 就绪不打断 B。
- A 为最早入队但仍下载中的高优先级消息，B/C 为已准备的同级消息时先播放 B/C；若 A 在后续选择前就绪，则按其原始入队序号参与同级排序。
- 接入方可以分别定义下载和播放优先级枚举，SDK 源码中不再存在固定等级枚举。
- 同资源重复消息保留，下载失败/过期后队列继续。
- release/clear 后没有旧回调启动播放或遗留文件保护。
- 增加有意义的队列与超时测试；执行实际 Gradle 构建验证。

## 范围

本次不实现礼物连击、业务合并、播放抢占、等待窗口或自动无限重试，不变更旧单条播放语义。
